# Локальные эксперименты Numerai

Первый эксперимент сравнивает обычную линейную Ridge
и LightGBM на одинаковой выборке Numerai v5.3, с целью `target_ender_60` и 42
признаками из набора `small`.

## Запуск

Перед продолжением на другой машине прочитайте [HANDOFF.md](HANDOFF.md).
Он содержит состояние экспериментов и команды восстановления моделей/Colab-пакета.

Из корня репозитория, Python 3.10 или 3.11:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-baseline.txt
.\.venv\Scripts\python.exe experiments\download_numerai.py
.\.venv\Scripts\python.exe experiments\numerai_baselines.py
```

Данные ожидаются в `downloads/numerai/v5.3/`: `features.json`, `train.parquet`,
`validation.parquet`. Для другой папки используйте `--data-dir`.
Загрузчик проверяет размер и SHA256, сохраняет `.part` для возобновления и
повторно не скачивает корректные файлы. Для проверки без скачивания:
`python experiments/download_numerai.py --verify-only`.

Открыть результаты и графики можно в `notebooks/01_numerai_baselines.ipynb`.
Для повторного обучения из ноутбука выберите интерпретатор `.venv` и переключите
`RUN_TRAINING` на `True`. По умолчанию ноутбук показывает сохранённые результаты.

## Протокол первого эксперимента

- До 200 случайных строк из каждой обучающей эры, seed=42. Строки с отсутствующей
  целью исключаются. Обе модели получают одни и те же строки.
- Пропуски признаков заменяются медианами обучающей выборки. Ridge также применяет
  StandardScaler, обученный только на train.
- Ridge: alpha=100, solver=cholesky. LightGBM: 500 деревьев, learning_rate=0.03,
  max_depth=5, num_leaves=31, min_child_samples=200, colsample_bytree=0.8,
  reg_lambda=1, max_bin=15, два потока. Это фиксированные исходные параметры;
  поиск гиперпараметров и early stopping на validation не выполняются.
- Оценка на полных эрах с `data_type=validation` и известным `target_ender_60`.
  После последней обучающей эры исключаются первые 13 недель validation:
  консервативный промежуток для горизонта 60 торговых дней с задержкой.
- Данные читаются порциями. Эра, разделённая границей порций, сначала собирается
  целиком, затем оценивается.
- Официальный `numerai_tools.scoring.numerai_corr` вычисляется по каждой эре.
  Среднее даёт одинаковый вес эрам, независимо от числа строк.
- CORR Sharpe = среднее / стандартное отклонение с ddof=0, без годового пересчёта.
  Просадка считается по накопленной сумме CORR и не является просадкой портфеля.

Сводные таблицы, метрики по эрам, график и параметры запуска сохраняются в
`experiments/results/numerai_baselines/`. Обученные модели и прогнозы сохраняются
в `downloads/numerai/baseline_artifacts/`, который игнорируется Git.

Для масштаба выборки доступны `--rows-per-era`, для числа деревьев — `--trees`.
Повторный запуск в ту же папку перезаписывает её результаты; для отдельного
эксперимента укажите `--output-dir`. Модели и прогнозы также перезаписываются.

Это предварительный ориентир на ограниченной выборке и небольшом наборе
признаков. Валидация уже просмотрена: если впоследствии настраивать параметры,
следует выделить отдельные периоды для настройки и новой окончательной оценки.

Источники: [данные](https://docs.numer.ai/numerai-tournament/data),
[CORR](https://docs.numer.ai/numerai-tournament/scoring/correlation-corr).

## RFR с опорными точками LHS

После первого эксперимента запустите:

```powershell
.\.venv\Scripts\python.exe experiments\numerai_rfr.py
```

Используется та же выборка: 200 строк из каждой эры, seed=42. Её реконструкция
проверяется совпадением коэффициентов повторно обученной Ridge с сохранённой
моделью. RFR получает 128 опорных точек LHS, исходную Kf с C=1, n=t=100000,
sig=0, method_reg=ridge, alpha=0.1 и свободный член. Пропуски заполняются
медианами train; масштаб исходных признаков не изменяется.

Оценка проходит на тех же эрах и строках. Метрики базовых моделей используются
повторно; новые результаты записываются в `experiments/results/numerai_rfr/`.
Ноутбук `notebooks/02_numerai_rfr_lhs.ipynb` показывает сравнение трёх моделей.
Модель, обучающая выборка и прогнозы RFR записываются в
`downloads/numerai/rfr_artifacts/` и игнорируются Git.

Для отдельного эксперимента на 256 точках:

```powershell
.\.venv\Scripts\python.exe experiments\numerai_rfr.py --n-support 256
```

Результаты: `experiments/results/numerai_rfr_256/`, модели и прогнозы:
`downloads/numerai/rfr_artifacts_256/`. Ноутбук сравнения:
`notebooks/03_numerai_rfr_lhs_256.ipynb`. Результаты на 128 точках сохраняются.
При наличии сохранённой выборки она используется повторно с проверкой хеша ID
и совпадения коэффициентов повторно обученной Ridge. Дополнительно измеряются
время чтения validation, подготовки, предсказаний, вычисления CORR и записи.
Для восстановления артефакта без валидации используйте `--train-only`.
Этот режим отмечает `run_status.json` и не обновляет исторические таблицы CORR.

## Проверка float32 и GPU

Полная валидация запуска на 256 точках остановлена по запросу пользователя.
Сохранённая обученная модель используется для отдельной проверки точности.

```powershell
.\.venv\Scripts\python.exe experiments\numerai_float32.py --eras 64
```

Сравниваются исходный float64-инференс, матричные расстояния float64,
прямой float32, float32 с вынесением постоянной C*n в свободный член и
повторное обучение Ridge в float64/float32 на тех же 256 опорных точках.
Основная библиотека не изменяется: новый вычислительный код пока находится
в `experiments/rfr_precision.py`.

Используются первые 64 полные допустимые эры, поэтому CORR в этой проверке
нельзя сравнивать со средним по всем 640 эрам предыдущих экспериментов.
Инференс измеряется после прогрева, три раза в меняющемся порядке:
в таблице указана сумма медианных времён по эрам, без чтения файлов и CORR.
CPU использует два потока. Время обучения включает построение матрицы и SVD.
Результаты: `experiments/results/numerai_float32/`.

Для Google Colab откройте `notebooks/04_numerai_rfr_float32_colab.ipynb`,
выберите GPU и загрузите подготовленный
`downloads/numerai/float32_benchmark/colab_inputs.npz`.
Ноутбук сравнивает исходный CPU float64, PyTorch CPU float32, GPU float32
с передачей данных и без неё, затем обучает Ridge на GPU в float32.
Время CUDA измеряется с синхронизацией; TF32 отключён.
Новый GPU-код ещё не исполнялся на GPU и требует проверки в Colab.
