# Передача контекста: RFR, Numerai и float32

## Цель пользователя

Пользователь хочет доработать RandomFunctionsRegressor и проверить его на
Numerai. Главный недостаток исходного варианта — число коэффициентов равно
числу обучающих строк. Теперь реализован режим с фиксированным числом опорных
точек LHS: `y(x) = b + sum_j a_j * Kf(||x-z_j||²)`.

Пользователь просил сохранить его исходную `Kf`. Дальнейшее развитие библиотеки,
выбор опорных точек по реальному облаку данных и организация обучения/данных
в Colab остаются темами следующего обсуждения. Браузерную автоматизацию
пользователь отложил и решил попробовать подключение Colab из VS Code.
Запрос сохранить и запушить эту ветку согласован; слияние с main не запрашивалось.

## Что реализовано

- `RandomFunctionsRegressor/lhs.py`: LHS в пределах min/max **train**, постоянные
  координаты сохраняются, коэффициентов ровно `n_support`, отдельный intercept.
  Ridge SVD с penalty `alpha + sig²`; остальные LS-методы используют `sig²`.
  Расстояния и прогноз считаются пакетами через SciPy; матрица обучения остаётся
  плотной `training_rows × n_support`. Библиотека использует float64.
- `n_support=None` сохраняет исходный режим. Известные ограничения старого
  режима, включая старую ridge-ветку, отдельно не исправлялись.
- `experiments/numerai_baselines.py`: воспроизводимые Ridge и LightGBM.
- `experiments/numerai_rfr.py`: LHS 128/256, отдельные папки, проверка выборки
  через ID-хеш и повторное обучение сохранённой Ridge; `--train-only` позволяет
  восстановить модель без полной валидации.
- `experiments/rfr_precision.py`: экспериментальные матричные расстояния
  `||X||² + ||S||² - 2XSᵀ`, float32 и перенос константы `C*n` в intercept.
  Последнее алгебраически сохраняет модель и уменьшает потерю точности.
- `experiments/numerai_float32.py`: парная проверка скорости/точности и экспорт
  небольшого `colab_inputs.npz` с подготовленными train/validation.
- `notebooks/04_numerai_rfr_float32_colab.ipynb`: самостоятельный PyTorch GPU
  эксперимент; TF32 выключен, время CUDA измеряется с синхронизацией.
  Есть CPU, GPU compute, GPU с передачей данных и обучение Ridge SVD на GPU.
  Его синтаксис проверен, **на GPU он ещё не запускался**.

## Данные и протокол

Numerai Tournament, **v5.3**, цель `target_ender_60`, набор `small`: **42 признака**.
В полном наборе 3555 признаков; в этих экспериментах они не использовались.

- train: 2 746 268 строк, эры 1–574.
- validation-файл: 4 169 448 строк, эры 575–1240, включая другие типы данных.
- Обучение: до 200 случайных строк из каждой train-эры, seed=42,
  **114 800 строк**. Медианы только train, Ridge дополнительно StandardScaler.
- Полная оценка: `data_type=validation`, известная цель, пропуск первых 13 эр
  после train. **640 полных эр, 4 003 128 строк, эры 588–1227**.
- Официальный `numerai_tools.scoring.numerai_corr`, равный вес каждой эры.
  CORR Sharpe = mean/std(ddof=0), без годового пересчёта.
  Просадка накопленного CORR не является просадкой портфеля.
- Validation уже просмотрена. Подбор настроек потребует отдельного периода
  настройки и новой окончательной оценки; рост на этой выборке не доказывает
  улучшение на будущих данных.

## Завершённые результаты

На всех 640 эрах:

| Модель | mean CORR | CORR Sharpe | Положительные эры |
|---|---:|---:|---:|
| Ridge | 0.01273855 | 0.88838 | 81.875% |
| LightGBM | 0.01202487 | 0.82529 | 78.281% |
| RFR LHS 128 | 0.01292607 | 0.92199 | 82.969% |

RFR: C=1, n=t=100000, sig=0, alpha=0.1, seed=42, intercept=True,
batch_size=1024. Fit 128 точек — 37.66 s; 1421.55 s всего включают чтение,
обучение, прогноз, CORR и запись, **это не чистое время инференса**.

256-точечная float64-модель обучена за 122.56 s. Пользователь остановил её
полную валидацию после сообщения о 100/640 эрах. Полного mean CORR для неё нет.
Статус: `results/numerai_rfr_256/run_status.json`; частичный parquet нельзя
считать завершённым результатом. Ноутбук 03 — шаблон незавершённого сравнения.

Отдельная проверка 256 точек выполнена на **первых 64 эрах (588–651),
372 650 строках**. Эти средние нельзя сравнивать со средними на 640 эрах:

| Вычисления | mean CORR | Время прогноза, s | Ускорение к исходному |
|---|---:|---:|---:|
| Исходный SciPy float64 | 0.01948956 | 59.17 | 1.00× |
| Матричные расстояния float64 | 0.01948956 | 36.37 | 1.63× |
| Прямой float32, прежние коэффициенты | 0.01949940 | 18.29 | 3.24× |
| Центрированный float32, прежние коэффициенты | 0.01949050 | 17.31 | 3.42× |
| Повторное обучение в центрированном float32 | 0.01948956 | 18.64 | 3.17× |

Для центрированного float32 без переобучения RMSE к исходным предсказаниям
1.24e-6, максимум ошибки 6.65e-6. Прямой float32 имеет максимум 3.24e-4.
После переобучения float32 RMSE 6.46e-5, максимум 7.90e-5: это другой вариант
проверки, его нельзя смешивать с простой сменой точности инференса.
Fit матричного центрированного варианта: float64 84.77 s, float32 51.66 s
(1.64×). Инференс измерен в 2 CPU-потока после прогрева, три повтора,
в меняющемся порядке: сумма медиан по эрам, без I/O и scoring.
3.42× включают смену вычисления расстояний; только переход float64→float32
в матричном варианте даёт около 2.10×. GPU-результатов пока нет.

Точные таблицы, конфигурации, замеры и графики сохранены в `experiments/results/`.
Ноутбуки 01/02 содержат исполненные результаты; 03/04 не исполнены.

## Восстановление на новой машине

Использовать Python **3.10 или 3.11**. Эксперименты исходно запускались на
Windows с Python 3.10.11; версии вычислительных зависимостей закреплены в
`requirements-baseline.txt`. LightGBM 4.7.0 падал с native access violation
даже на маленьком тесте; проверенная версия — **4.6.0**.

```powershell
git clone --branch feature/lhs-rfr-numerai https://github.com/AlexeyKozhakin/RandomFunctionsRegressor.git
cd RandomFunctionsRegressor
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-baseline.txt
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

На Linux/macOS заменить `.\.venv\Scripts\python.exe` на `.venv/bin/python`.
Не использовать `--system-site-packages` на новой машине: зависимости явно
заданы. PyTorch не является зависимостью основной библиотеки или CPU-тестов.

Для скачивания около **8.37 GiB** public-данных v5.3 (features/train/validation):

```powershell
.\.venv\Scripts\python.exe experiments\download_numerai.py
.\.venv\Scripts\python.exe experiments\download_numerai.py --verify-only
```

Аккаунт/API-ключ Numerai для public-скачивания не нужен. Скрипт использует
официальный GraphQL API, временные URL не сохраняет, проверяет размер и SHA256
по `experiments/numerai_v5_3_manifest.json`. Существующие корректные файлы не
скачиваются снова, `.part` возобновляется, некорректный итоговый файл не
устанавливается. При несовпадении существующий файл не перезаписывается.
Путь можно задать `--output-dir`, но train-скрипты пока читают стандартный
`downloads/numerai/v5.3`; для другого расположения нужна отдельная доработка.
При недоступности v5.3 не переходить незаметно на другую версию.
Numerai может обновить содержимое файлов под прежней версией; в таком случае
проверка старого размера/SHA256 намеренно остановится. Для точного повторения
понадобится отдельная копия исходных parquet, либо явно согласованный новый
эксперимент с обновлённым манифестом. Исторические файлы локально сохранены в
`downloads/numerai/v5.3/`; Git их не переносит.
Для работы оставить запас на модели, прогнозы и временные массивы; 12–15 GiB
свободного диска — разумный минимум сверх окружения.

Восстановить модели и пакет для Colab без полной RFR-валидации:

```powershell
.\.venv\Scripts\python.exe experiments\numerai_baselines.py
.\.venv\Scripts\python.exe experiments\numerai_rfr.py --n-support 128 --train-only
.\.venv\Scripts\python.exe experiments\numerai_rfr.py --n-support 256 --train-only
.\.venv\Scripts\python.exe experiments\numerai_float32.py --eras 64
```

Эти команды перезаписывают соответствующие экспериментальные таблицы/артефакты.
Проверить `git diff` после повторного запуска; исторические результаты уже есть
в Git. Для полной повторной оценки RFR убрать `--train-only` и сначала оценить
128 точек, затем 256: их таблицы сравниваются с текущими baseline-результатами.
Проверки ожидают тот же протокол обучения; смену версии данных/числа sampled
строк проводить как отдельный эксперимент, а не поверх этих результатов.

Не входят в Git: `downloads/` (данные, модели, прогнозы, colab_inputs.npz), `.venv`.
Для текущего Colab-теста готовый пакет имеет размер около **13.4 MB**; для
другой машины он создаётся последней командой или копируется отдельно с
проверкой содержимого. Скачивание всех данных нужно для воспроизведения с нуля,
а для запуска подготовленного GPU-теста достаточно этого пакета и notebook 04.

через официальное расширение **Colab от Google** в VS Code. Подтверждения

browser-upload fallback, который в VS Code не нужен при заранее загруженном
файле. CSV результатов сохраняются в среде Colab; browser-download выключен
по умолчанию для VS Code. Ядро удалённое: локальные Windows-пути там отсутствуют.
